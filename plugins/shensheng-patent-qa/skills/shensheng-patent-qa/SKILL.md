# 申晟专利独立质检

本技能已内置于机械专利撰写插件，同时保留可单独安装、调用的质检入口。撰写流程在实际初稿或改稿文件生成后、最终交付前默认执行本技能，无须用户另行提出；用户当次明确限定范围、要求跳过或仅作尚未成稿的讨论时按其要求执行。核心检查、逐处扫描及报告格式均由本包提供，不依赖另装上游技能或外部平台。

## 先读取

- 必读本包[审稿方法与证据](references/review-method.md)，按实际权项、因果和工况执行，不能只做形式扫描。
- 名称与标号核对必读[部件名称与标号逐处核对](references/component-occurrences.md)，逐次建立位置清单，并用[逐处扫描脚本](scripts/audit_component_occurrences.py)辅助核查。
- 机械结构案另读[机械图文与真实修订复核](references/mechanical-review.md)。本机已有 `mechanical-patent-drawings` 时，可追加其参考；用户当次要求和有效底稿优先。
- 报告及整改复核按本包[审核记录格式](references/report-record.md)，默认交 Markdown。已有本地 `patent-draft-review` 时，可复用其更详细的方法及兼容的 HTML 生成器，但它不是核心质检的必装条件；使用时核对其版本和数据格式。上游出处保留在 metadata，公开参考为 [v0.6.1 固定提交](https://github.com/KrisMiao97/patent-review-kit/tree/676ae000af132d7db9ba59821d8fcd2234288fdb/patent-draft-review)。
- 引线长短和线形按用户已确认样例核对，样例由使用者在本地提供。没有可用样例时，执行本包机械复核并记录样式基准未核，不将数值接近视为整体通过。不会随公开包提供任何案件样图。

逐处扫描脚本仅需 Python 3 标准库，不依赖文档处理库。优先使用现有环境；仅需人工审稿时不要求安装 Python。可选上游离线 HTML 报告需 Python 3.10+ 及完整本地组件；不可用时继续交付同包 Markdown 记录，并说明未生成 HTML，不为报告擅自升级整套环境。

默认仅做稿内质检，复用已完成且对应本版本的检索材料；不因上游包含检索流程而重复启动外部检索或向其他平台发送稿件。原撰写流程已要求的实际专利检索继续由该流程完成，质检读取其证据及未核事项。用户指定 Work Buddy、DeepSeek 或其他复核平台时再按其要求追加，本入口不依赖这些平台。

## 独权保护层次与唯一名称

独权必须上位、简洁、抽象，正式稿同一特征使用唯一名称。撰写与审核均先读同包[独权保护层次与特征名称](references/claim-scope-and-names.md)。保护层次、技术支持、正式名称、标号图面及成品分别验收；不能以材料有记载、存在检索区别、字数减少或扫描通过代替独权必要性判断。具体做法只维护在共同细则，分发副本由公开规范源生成，禁止另改成相反标准。

最终命名检查启用部件核对参考的规范名称模式；历史别名只供识别和追溯，同号不豁免正式稿异名。正常数字标号括号、形态说明和原文引用按细则分别处理。

机械稿另将**特征引入与归属**单独验收：按[共同细则](references/claim-scope-and-names.md#新特征先交代归属和设置关系)，沿首次引入句、已引入母件或真实引用链、所属/位置/连接及后续展开核实际文字，并在现有审核记录定位原句及整改。名称或编号出现过、图例已列、平行从权已介绍及机检通过，均不能替代此项；同句清楚引入可接受，不要求把全部实施例组成上提独权。

配对支路、部分量词、方向回指、外部配合对象及删除标记联动按[共同细则](references/claim-scope-and-names.md#配对关系量词与配合对象)逐处核原文和依据。不能以句子更短认定范围未变，也不能只撤某幅图的数字便关闭全套同步问题。

## 冻结文件并独立审阅

1. 确认当前有效版本、申请类型、程序阶段及本轮修改范围，列出实际 Word、正文、独立附图 PDF／原图、交底和必要模型的路径及摘要值。优先接收用户指定的文件，不要求用户为质检重新制作本技能格式的目录。交底无正式权项时按技术方案检查，不编造权项；外观或仅附图任务只核适用的形式与图面，说明功能因果为何不适用。
2. 默认另启未参与本轮起草的独立子代理，给冻结文件路径、原始技术依据、审核范围和上述技能路径。要求它实际读取文件、渲染看图并返回证据，不给起草者“已通过”的自评或预设结论；必要的用户确认事实保留来源标识。审阅者只出意见，起草者负责核实和整改。
3. 无独立执行条件时完成能做的本地复核并明确标记“独立质检未完成”，不把起草者自检冒充独立审阅。已取得但未实际查看的附图记为未核读，不能以 OCR、图片数量或标号集合代替目视。

## 五类检查

| 类别 | 实际检查与证据 |
| --- | --- |
| 方案逻辑 | 沿问题及原因、组成／步骤、连接／传递、动作条件和效果还原作用链；检查状态切换、边界及异常工况、相互矛盾和缺少中间环节。区分原文事实、工程推断与待验证假设。 |
| 公开充分性风险 | 查关键构造、配合、动作顺序及必要条件是否有据可实施，概括分支是否有对应教导；指出缺哪项信息、影响哪个方案及应补什么证据。不能把没有尺寸、没有测试或写得简短直接等同于公开不充分，也不擅自补造结构。法律定性核实适用的官方依据。 |
| 形式与支持 | 逐项核真实引用路径和累计限定、先行基础、术语及标号、说明书支持、正式栏目、摘要、图号及首次引用顺序。按机械撰写风格检查权利要求1是否有可概括的具体形式、可下沉的实施细节或重复表述。有指定或已确认模板时，将实际 Word 和 PDF 与母版对应部分核对分节、样式、页眉页脚、图号和页码。既有机检只作辅助。 |
| 标记落点 | 逐图、逐次出现、逐根辨认引线结构端或箭尖，核对所指实体、孔槽或配合面、正文定义、同号跨图归属、装配及遮挡状态。有模型时回看同源几何；只有距离接近某条线不算确认了目标部件。 |
| 引线与图面 | 在最终页逐根放大看曲线全长、整箭、线尾到数字的间隙和完整字框。与相邻引线、轮廓、剖线及装配虚线核对交叉、压线、贴行和真实净距，记录各处处理结果。再按最终图幅看 S 形、线宽字号和标号能否清楚辨认。美观标准单列。 |

机械图面以同一标号在某张图中的一次出现为一行，至少记录图号／页码、标号、目标部位、实际落点依据、引线及邻线检查结果、关联意见号。缺少清晰图或模型依据时写具体未核位置。

## 名称与标号逐处验收

- 依据核定术语表建立唯一正式名称—标号对照，另登记历史名称和简称用于识别残留，不允许在正式稿交替使用。对权项、主方案、具体实施方式、摘要及图名/标记表中每次出现按相应栏目逐处核查，保留位置、上下文、实有标号、名称状态及依据。其他位置已有正确名称或标号，不能替代当前这一处的检查。
- 先登记各栏目核定的标号格式，再处理漏号、错号、同名异物、同物异名、并列省略和代词。省号栏目及确实不同的对象逐段或逐处写明依据。词面嵌套、别名和同名不同零件须人工判定，不能对同名词整篇豁免或直接批量补号。
- 实用新型说明书“实用新型内容”章节依共同细则不带部件附图标记，配置`forbidden`并查残留，正式名称检查保持开启；具体实施方式等按其核定规则核号。不能因本章省号而跳过名称，或误删图号和技术数值。
- 完整审稿覆盖全部权项、正文、标记表和本轮全部附图。改后对实际交付副本重跑适用的全稿名称标号扫描；人工核读按下节对差异及关联范围复核，未变部分满足条件时复用原完整记录，并目视修改页及对应图面。报告登记实际覆盖、每处异常的处理和未核原因；只有集合匹配、局部抽查或语义通读时不得声称全稿逐处完成。

## 集中审阅与差异复核

- 首轮对实际文件完整独立审阅。集中核实一批意见、同步整改后，再生成受影响的 Word／PDF，避免每条意见都重建全套；沿用现有问题记录，不新增报告或审批。
- 后续复核差异及关联引用链、同号跨图和邻近引线；字体、视角、比例或几何改变时，对该图最终全图筛查并目视。未变部分仅在原始依据、规则及样式、范围、阶段和模板仍适用且有原记录时复用。用户指出漏检时，对应及同类旧通过失效。
- 核心权项变化由独立审阅者重查，并交回撰写流程对受影响特征和组合补检；不能据初步检索或文件摘要免除适用核读。
- 同时交付交底与申请时，可在同一审阅任务中分别核读两份实际成品并记录范围、依据与结论，共同技术底稿不替代各自质检。所有实际交付副本仍须渲染、隐私清理和清理后复验。

## 整改及复核

- 每条意见有稳定编号、严重程度、文件及页／项／段／图位置、原文或图像证据、影响、建议和处理状态。先核实再采纳，误报写驳回依据；材料缺口列待确认，不为关单补造事实。
- 对已授权且有依据的错误直接整改并同步正文、权项、摘要、标记表、合册／分册 Word 和独立图 PDF。已核定范围或仅局部改稿，保持本轮授权边界；需用户选择的实质方案另列，不自行替用户决定。
- 复核更新后的实际成品，逐条关闭意见，并连查受影响的引用路径、图页、同号其他视图和相邻引线。影响方案或核心权项的改动由独立审阅者重查。复用旧记录须核对文件、依据、用户要求、规则、阶段及范围均未变化；用户指出漏检时，对应旧通过结论失效，文件摘要不变也不能替代重新判断。
- 不因反复改写就认定缺证据问题已解决。缺事实或连续复核无新增依据时，完成其余可做工作，明确剩余问题及影响；案卷沿用既有轮次规则，不由质检另造无限循环或额外轮次。

## 报告与交付

默认在当前工作区 `outputs/patent-qa/{案名}_{时间戳}/` 保存内部审核数据、名称标号逐处表、逐图逐根记录、整改复核记录和按本包格式编写的 Markdown 审核报告。所有适用核心检查及报告均可离线完成；专利检索或最新法律依据另按本轮授权及实际工具核验。报告生成、独立审阅、技术判断、目视核图和问题整改分别记状态。未执行新检索时仍登记全部独权和未检索范围，不伪造新颖性或创造性结论。

已有兼容的本地上游组件时可另行生成离线 HTML，并按其原有数据格式与页面验收规则检查，不将本包记录直接宣称为上游兼容数据。未生成 HTML 时在交付状态注明，不影响已实际完成并有证据的核心检查。

记录所审文件及复核文件的摘要值，使报告对应实际交付版本。报告交付说明已核范围、未核项及关键遗留问题；不能用“报告已生成”代替“问题已解决”。案卷只读取并归集已有质检结果，不重复启动审核。

最终交付副本产生后执行用户 AGENTS 或当次要求中的隐私清理并重新核验可打开、内容及图页完整：Word／PDF／HTML 及打包副本均清除不属于交付内容的身份、工具、时间和内部路径等元数据；需要真实修订或批注时保留其功能并匿名化身份。清洁正文清除附带修订、批注和版本历史。清理后复查实际交付件的图文与版式，保存最终摘要值及结果；内部日志与审核源数据不混入交付包。
