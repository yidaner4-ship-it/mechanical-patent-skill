# PDF 文档辅助

这是**独立公开辅助版本，并非官方缓存包**。本目录不分发官方 PDF 技能、专有运行时、应用程序、字体或客户文件。新代码版权为 `2026 Mechanical Patent Toolkit contributors`，按仓库 MIT 许可发布。`requirements.txt` 仅声明公开第三方 Python 依赖；安装由使用者在自有环境完成。Poppler 的 `pdftoppm` 需本地另行准备。脚本不联网、不安装应用。

## 读取与生成

- 先检查 PDF 页数、页面尺寸、旋转、文本层、图像页、书签/表单以及数字签名。文本提取仅能证明提取到的文字，不能证明图形、附图或整页阅读完整。扫描件需要另行 OCR，并标明识别来源和不确定字词；不得把推测补成原文。
- 读取可采用 `pypdf.PdfReader` 的 `pages`、`page.extract_text()`；空文本不等于空白页。遇到加密或签名文件，不覆盖源文件，先取得获准的独立可处理副本。
- 生成正式 Word 同版 PDF 时，从核定 Word 导出并核对渲染，使用 `documents` 辅助技能。简单独立 PDF 可用公开库 ReportLab（可选，不随包分发）；明确页面大小、边距和可嵌入的授权字体。多页专利正文优先沿用用户 Word 母版，避免另起一套版式造成版本差异。
- 附图采用独立视图一图一页、完整墨迹居中和页脚图号；短 S 引线的参数与验收统一引用 `mechanical-patent-drawings`。权项内容及图文对应由专利质检负责，PDF 工具的成功退出码不能代替验收。

## 本地渲染与逐页检查

```bash
python scripts/render_pdf.py reviewed.pdf --output-dir pdf-pages --dpi 150
python scripts/render_pdf.py reviewed.pdf --output-dir pdf-pages-2 --pdftoppm /path/to/pdftoppm
```

从本技能目录运行。脚本优先使用显式路径，其次查找 PATH，并识别常见 macOS 路径；Windows 可传入 `pdftoppm.exe`，Linux 通常使用 PATH。输出目录须不存在或为空，不覆盖原 PDF。逐页检查页面数量、缺字、透明图像、线条、表格、页眉页脚、图号、方向及裁断；放大核对细引线和真实落点。记录实际检查范围，不能将“已生成 PNG”描述为“已目视验收”。

## 清理独立交付副本

```bash
python scripts/privacy_scrub.py reviewed.pdf clean.pdf
```

脚本使用 `pypdf` 克隆文档，移除文档信息字典、文档及对象级 XMP、附件名称树、文件附件注释、关联文件，以及自动执行动作/脚本相关项；生成后重新读取并检查这些项目。拒绝覆盖源文件或已有目标，拒绝加密和签名文件。清理会移除附件和交互动作；需要保留这些内容的交付物应另行审查，并明确允许的范围，不能直接运行后当作完整原件。

本工具不能识别页面正文、图片 EXIF、隐藏图层、OCR 字符、表单值或任意私有二进制中的全部身份信息。核对清理前后的可见内容和页数、渲染全部页面；表单、书签、超链接等如属于交付要求，也需实际检查。将元数据检查和人工核对范围写清楚，不声称彻底自动去隐私。

对 Word 导出件、分册、交付目录副本及 ZIP 内 PDF 逐份复查。不要包含不属于交付内容的嵌入源文件、原始客户文件、账号、模型、运行时或本机缓存。最终报告包括实际输出、工具版本或依赖缺口、目视检查范围及待确认事项。
