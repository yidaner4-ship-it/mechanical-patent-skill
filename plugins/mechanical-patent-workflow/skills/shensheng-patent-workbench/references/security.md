# 凭据、外发与无痕边界

## Key

- Key 只存 macOS Keychain，服务名 `com.shensheng.codex.patseek`，账户 `patseek-api`。
- 禁止在聊天、`--api-key`、`.zshrc`、`.env`、报告、Excel 或调用日志中出现 Key。
- `scripts/workbench keychain set` 由 `/usr/bin/security` 自行隐式读取 Key；`check` 只确认存在，不显示。

## 无痕调用

`scripts/workbench patseek ...` 默认：

- 从 Keychain 或当前进程环境读取 Key；
- 拒绝 `--api-key`；
- 强制跳过上游缓存；
- 在进程内禁用缓存读写、调用日志、历史去重和基于历史的节流；
- 不创建 `~/.cache/patseek` 新文件。
- `bool/semantic/patent` 强制用 `--query-file <0600文件>` 或 `--query-stdin` 在包装器进程内注入私密位置参数，使原始内容不出现在操作系统进程参数中；原始位置参数会被拒绝。
- 付费包装器强制接收 `--case-dir` 与 `--query-hash`，重新计算 HMAC，并核验 running 预留的引擎、`paid_command`、市场、页码、每页条数、详情增强模式和实际查询；同一预留只能启动一次执行，并输出供完成登记使用的一次性 `attempt_id`。该标识同时保存在权限为 `0600` 的案件状态中，避免进程在落盘后、输出前中断而无法核销；它不是 API Key 或检索式。
- 包装器在整个收费请求期间持有逐查询的进程级文件锁；原调用仍活跃时，即使已人工标为 `uncertain` 也不得重试。所有已经启动的失败/超时/不确定记录都必须核对服务端后重试，上游已经成功返回的记录禁止改写成可立即重试的普通失败。
- 生产入口不接受任意 `--client`，只加载与本 Skill 同一受信 Skills 根目录内、当前用户所有且不可被其他用户写入的 PatSeek 客户端；所有上游选项使用精确白名单，拒绝 argparse 缩写。

无痕模式不消除：Codex 任务记录、PatSeek 服务端记录、上游响应/错误输出、用户显式指定的附图/报告/案件文件。它只承诺原始查询不进入操作系统 argv、隐式缓存或 calls.log，不能承诺终端和服务端完全无记录。无痕模式也失去上游跨进程近似去重和本地节流；因此收费调用前必须先用 `reserve-query` 原子登记 HMAC 查询摘要，调用时传入同一案件与摘要，调用后用包装器返回的 `attempt_id` 执行 `complete-query`，并依赖服务端 429 退避。工作台锁和 PatSeek 包装器都以单一文件描述符核验查询文件的所有者、普通文件类型、权限和大小；原始检索式不得作为 argv 参数。

## 外发

仅在当前使用者授权范围内外发必要检索内容，但仍实行数据最小化：删除客户身份、内部项目号、报价、联系人及与检索无关的商业信息。CNIPA Mode D 使用 HTTP/浏览器自动化时，不发送未公开完整方案，只使用已去标识化的必要通用术语。

显式案件文件按敏感数据处理：目录权限优先 `0700`，JSON/日志优先 `0600`；对外发送前另存脱敏副本。
