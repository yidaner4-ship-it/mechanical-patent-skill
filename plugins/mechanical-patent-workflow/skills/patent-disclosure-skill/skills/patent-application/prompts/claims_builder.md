# 申请文件 · 权利要求书

机械结构类发明和实用新型先读[申晟撰写风格](../../../../mechanical-patent-drawings/references/shensheng-drafting-style.md)，按部件名称、括号标号及必要结构关系分段。下文的方法步骤、软件系统模块不编号等规则只用于相应保护对象，不据此取消机械产品的件号或改成步骤权项。

先有 `application_plan.yaml` 的 `claim_tree`。正式权要里禁止待确认标记、质量分。

按[共同细则](../references/claim-scope-and-names.md)起草和复核独权层次及正式名称；不要把完整实施例压缩改名后仍整组搬入独权，也不要将其整段转移到一条从权。上位后继续用同一名称描述具体构造，不在后文或标记表追加括号别名。

1. 先独立权利要求 1，再按 `claim_tree.dependents` 的 `id` 顺序写从属。「……，其特征在于……」。独立权项不引用其他权项；从属只引用在先权项。
2. 机械产品（发明或实用新型）件号与结构台账 `parts`及必要子特征 `features`一致，具体按本案核定编号口径。
3. 发明方法独权用「包括以下步骤：」+「步骤一，…；步骤二，…」。权利要求 1 每个「步骤N，…」必须与 `invention_figures.yaml` 流程图节点 `label` **逐字同义**（脚本按子串对照，对不上会报 `STEP_MISMATCH`）。匹配分构成、双阈值含义、窗口长度等细节只进从属，不要写进权利要求 1。不要另编 S1 或 201。从属展开某步时用「步骤一…的方法如下：」「步骤11」这类嵌套，仍不要改用 S1。
4. 软件系统独权写模块名称及连接／功能关系，不用机械件号。机械总成不因名称含“系统／装置”取消标号。第二条独权按自身保护对象组织，不误写成从属。
5. 计算公式默认放说明书。从属用文字限定计算关系（「按…加权并扣除…得到匹配分」），不要把整段 LaTeX 写进权要。交底有 `formula_plan.yaml` 时：权要用语须与计划中的符号含义同义，式面只在说明书。
6. 去掉宣传语（词库 `references/promo_terms.yaml`）。效果放说明书有益效果与实施例。参数表、对照表只写说明书，不要写进权要。
7. 「所述」须有前置：该词在本项更早位置或在先引用权项中已出现。不要一上来就「所述匹配分」。

分份：`权利要求书.md`。

```bash
python skills/patent-application/tools/audit_claims.py <产出>/权利要求书.md
```

已有件号登记表时加 `--register <产出>/件号登记表.yaml`，优先按登记名称及核定别名识别前置；无登记表时启发式提示仍须人工核实，不能把共同词干当完整部件。

`APPLICATION_CLAIMS: ok=0`先核实：确定错误先改，误报记录驳回依据，不能迎合机检改坏正确文字。警告同样核实实际引用链和先行基础，不以“记清单”替代确定错误整改；按共用收尾区分定稿状态。机器通过不等于支持或授权。
