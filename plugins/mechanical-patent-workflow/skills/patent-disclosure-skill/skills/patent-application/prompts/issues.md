# 申请文件 · 问题清单

主文件写完后写 `问题清单.md`。**不要**写入权利要求书、说明书、摘要或附图。

清单区分确定错误、非阻塞待确认、影响定稿的事实／文件／验收缺口，按[共用收尾](../../../../mechanical-patent-drawings/references/drafting-and-review.md#共用收尾)处理。每项记录位置、影响、依据、处理与完成状态；已有质检记录可引用，不重复建单。确定的缺前置、超字数、错引错号先整改；机检误报核实驳回。缺图或关键事实未核时继续其他有依据部分，但不得把阶段成果称为正式定稿。发明人／申请人未填非阻塞；OMML失败须核对实际显示与可编辑要求后说明状态。
外观另列：落面未覆盖、虚线范围未锁或各视不一致、省略原因用语不合指南、图照片混用、投影关系/比例不一致、图幅或 DPI 超限、线稿含尺寸线/中心线/阴影线/图内图号、透视棚拍充当正投影、默补假面、新事项风险。  
抄 `APPLICATION_CLAIMS` / `APPLICATION_NUMERALS` / `APPLICATION_FIG` / `APPLICATION_FIG_PLAN` / `APPLICATION_SUPPORT` / `VIEW_CHECK` 的结果。`标号核对.md` 中的串号、未登记号一并列入。外观把 `视图检查清单.md` 的不合格/待核摘要进本清单。

不因备选或局部缺口删掉其余有依据成果；也不以列清单代替确定错误整改或生成失败修复。无额外缺口仍落盘清单，可引用机检和质检记录。外观原图按专用分支保留，不默补假面；不合格项说明尚未完成的视图范围。

## 对话末尾（强制，与落盘同一条回复）

四件套路径说完之后，**最后**用固定标题，不可省略、不可只写「详见问题清单」。

## 交付后请确认

1. **内容待确认 / 可调整：** 写出 `问题清单.md` 的工作区相对路径（如 `outputs/patent-application/{案件}_{时间戳}/问题清单.md`），明确请先打开该文件再改 Word 或上传。用短句摘要须人处理的条目（发明人未填——非阻塞、查新未复做、权要备选、PNG/OMML 失败、外观漏视/虚线/新事项、外观图幅/混交/投影等）。条目多则列要点，不要整文件粘贴。外观须同时给出 `视图检查清单.md` 路径。发明人/申请人/文头联系人未填**不得**写成案卷阻塞项。只有机器检查、没有内容缺口时：仍给出路径，并说明机器通过不等于授权、不等于客户端校验已通过。
2. **完成状态：** 说明实际是否完成适用的生成、检索、独立质检和成品核验；阶段成果写明未完成范围，不以“机器通过”替代定稿。后续改稿默认新时间戳目录，不重复请求已获授权的另存或检查。

未宣称已通过国知局附图审查或电子申请格式校验。不要在此节把交底围栏、案卷或专利地图列为下一步。
