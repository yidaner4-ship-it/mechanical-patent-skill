# 专利稿审阅公开兼容入口

这是本项目独立编写的公开兼容实现，非上游原包，不包含、替代或声称实现任何未随包分发的第三方程序。兼容范围是本文约定的审稿工作流和 `scripts/render_review.py --input JSON --output HTML` 入口；不承诺上游完整数据模式、页面或自动检查能力相同。

## 实际审阅

1. 冻结用户指定的实际 Word、PDF、独立图页及技术依据，登记版本摘要和本轮范围。另启未参与本轮起草的审阅者；无此条件时明确写“独立审阅未完成”。不要先提供起草者的通过结论。
2. 实际读 Word 正文、权项及 PDF；渲染并目视最终图页。文本提取、OCR、图号集合或报告生成不能替代看图。文件不能读取、图像不清或工具不足时，定位并登记未核范围。
3. 按[审稿方法](references/review-method.md)还原问题、原因、结构配合、动作条件及效果，查实施条件、工况和异常状态；核权项真实引用链及累计限定、术语、清楚和说明书支持。对独权的具体形式逐项试删：删除后核心技术关系仍完整的，考虑移入从属项，保留取舍理由。
4. 逐段核正文引图及首次实质引用顺序，逐图逐根核标引的实体落点、同号归属、完整字框、引线与邻线净距。记录图、页、标号、部位及目视依据；无图或未查看不能记作通过。
5. 每项意见记录稳定编号、位置、事实证据、因果或实施影响、建议和处理状态。区分原材料、用户确认、工程推断和待验证事项。事实不足就列缺口，不编造结构、测试或检索结论。
6. 起草者核实并整改有依据的问题，复核实际更新文件及受影响的引用链、图页、其他同号视图。关闭意见必须有修订位置和复核证据；不能仅凭已改写文字关单。重大结构或核心权项改动交独立审阅者复查。

正式法律判断及新颖性、创造性结论需要相应适用依据和实际检索证据；本入口本身不查询数据库。未经授权不把稿件上传其他平台。

## 输出

先按[记录模式](references/template-schema.md)整理实际审阅记录，再运行：

```bash
python3 scripts/render_review.py --input review.json --output review.html
```

脚本仅使用 Python 3.9+ 标准库，不联网、不读取 Word/PDF、不实施审稿。它会安全显示全部提供字段，包括未知字段；输出成功只表示 HTML 已生成。每页显式提示这不等于独立审阅、目视核图或审查通过。输入字段展示在报告内，因此交付前须按用户隐私要求清理不属于交付内容的身份、时间、账号、内部路径和其他数据。

按[报告验收](references/report-validation.md)检查对应版本、可读性、意见和未核项。需要 Word 时读 [Word 输出边界](references/word-output.md)；真实修订和批注按用户要求保留并匿名化，清洁稿移除修订历史及批注。只报告实际已完成的范围。
