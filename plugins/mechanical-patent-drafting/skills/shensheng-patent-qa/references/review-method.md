# 独立审阅方法

本包可独立完成核心审阅，不以安装其他技能或联网为前提。用户指定范围、有效底稿及已确认事实优先。外部法律依据、检索证据或特定工具确有必要而不可得时，继续审查可核部分，将受影响的判断列为未核。

## 确定实际审阅对象

冻结本轮正文、Word、独立附图及必要依据，记录文件名和 SHA-256。核清申请类型、程序阶段、保护对象、修改范围与已有意见。原材料、用户补充确认、审阅推断和待确认事项分别记录。复用旧审核须核对实际文件摘要值、审阅范围与原始依据仍一致。

由未参与本轮起草的审阅者读取冻结文件和原始依据，独立提出意见，不预先告知“已经通过”。起草者核实并整改。没有独立执行条件时仍完成本地检查，明确标注独立审阅未完成；收到报告不等于已经核实报告意见。

## 权项、支持与技术因果

1. 列全独立权利要求和保护对象。逐项记录从属引用，择一引用分别展开继承路径，核累计限定、先行基础、分支兼容及同一对象的名称。不能只检查当前项新增的一句话。
2. 将实际特征和必要配合回映到说明书段落、图中部位及原始依据。实施例之间的组合须有依据；概括后的关系仍应可辨认、可实施。区分独权必要结构、有后备价值的从权和仅需说明书展开的细节。修改范围由用户授权及材料支持决定。
3. 对每个独立方案还原“问题及原因 → 构造或步骤怎样作用 → 成立条件 → 直接效果”。指出具体证据和缺失环节，核对正文、权项与图示是否描述同一作用关系。没有尺寸、没有测试或文字简短，本身不足以认定无法实施。
4. 反查效果需要的信息能否实际获得，所选结构或路径能否利用这些信息，效果的精度和适用范围是否超过依据。测量、计算、估计与研发设想分别表达，不把目标当作已验证结果。
5. 对动作切换、阈值、可选结构和异常情况列适用工况，查初始状态、边界、接触或传递顺序、退出及故障状态。只审方案实际涉及的工况，不为填表增加技术事实。关键缺口写明影响哪条作用链、哪项权利要求及需要何种证据。

已有检索材料须对应当前特征和版本。没有执行检索时登记独权与未检索范围，不给出“未发现现有技术”或新颖性、创造性已通过的结论。需要法律定性时核对适用阶段的官方依据；依据不可得则保留判断边界。

## 全文与附图

按[名称与标号逐处核对](component-occurrences.md)检查每次名称及别名，登记栏目格式和精确例外。再人工通读字典外的简称、合称、代词及并列省略。脚本只识别已配置词，不证明全部部件已被字典覆盖。

按[机械图文复核](mechanical-review.md)实际查看每幅适用图及每次标记，核落点、同号归属、段内引图覆盖、装配和剖切关系。对摘要、正文、权项、图例和正式栏目逐一记录覆盖状态。图面不可读或工具不能显示时记录具体页、图和未核原因，不以 OCR、标号集合或资源一致代替目视。

## 核实、整改与最终复核

每项意见定位到原文或可见部位，写依据、影响和建议。先核实后采纳；误报写驳回理由，缺事实保留待确认。已授权且有依据的修改同步到相关权项、正文、摘要、标记表和图稿。局部改稿连查实际受影响位置，不扩张为未经要求的整篇重写。

整改后核实际成品及关联引用、同号其他图、相邻引线。核心方案改变时由独立审阅者重查受影响部分。缺证据不会因反复改写而自动解决；没有新增依据时，完成其余工作并明确遗留项及影响。

交付副本完成隐私清理后，重验可打开、文字、修订状态、分页及图面，记录每份最终文件的摘要值。按[报告记录规范](report-record.md)分别记录审阅、机检、目视、整改、报告生成及隐私清理状态。
