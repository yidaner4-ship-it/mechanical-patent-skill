# 部件名称与标号逐处核对

本项检查适用于机械文稿中已确立的名称和标号。按用户指定的标号习惯检查每一次出现，记录具体位置。同一句前面或其他段落已经有标号，均不能代替当前这一次的检查。

命名及保护层次的共同细则见[独权层次与正式名称](claim-scope-and-names.md)。历史别名用于识别输入和追溯旧稿，不表示最终稿可以交替命名；同号不能豁免同物异名。

## 文稿核查

1. 从实际标记表、权项和已核图中建立本案名称—标号对照，先确定各部件的唯一正式名称，再将历史名称或确指同一对象的简称登记为识别别名。例如「安装座」「环形安装座」可能指同一实体，但选定正式名后，不因同号而允许在最终权项、正文、摘要及图例交替使用。不同零件上的「安装孔」可能各指不同对象，须沿归属判断。具体形态可以用“采用环形结构”等句子说明，不另给同一特征命名，也不写成图例“安装座（环形安装座）”。
2. 先依据用户指令、认可范文或核定要求表，独立核定各栏目的标号格式，再生成段落配置；不能从成稿的现有写法推定正确格式。申晟当前默认：权项中的附图标记为`parenthesized`；说明书正文中需要尾随标号的部件为`bare`，包括适用的发明／实用新型内容和具体实施方式。摘要、技术领域、背景、图名或前置标记表按各栏目核定的省号、可选号或前置编号规则分别登记，不能全篇硬编码同一格式。用户本案明确指定其他格式时优先；这些政策仅针对部件名后的附图标记，正常解释和公式括号保留。不能把整篇同一个词统一设为豁免。
3. 对每处名称分别判定有号且一致、漏号、错号、同物异名、同名异物或经核定例外。名称嵌套按最长完整名称识别，例如「插拔上盖」中的「上盖」只记一次。「分隔壁段」中的「隔壁」不直接视为相邻通道的隔壁；「第一组出光通道」不自动当作单个通道。遇这种词面重叠须回查原句、母件和附图。
4. 对字典未覆盖的简称、合称、代词、并列省略和新引入部件进行人工通读，补充实际名称或逐处判定。例如「主机侧电连接件」内的「主机」与独立回指主机的用法不同。「安装孔」「开孔」应沿所属零件判定。自动匹配结果只是候选清单，不能据此直接批量补号。
5. 图面另按每图每次标号逐根核落点。对正文每处标号展开本段引图，确认所引图合计覆盖该标号及配合关系。纯名称或编号集合、图片资源哈希一致均不能代替逐处核查。

## 辅助脚本

`python scripts/audit_component_occurrences.py 五书.docx --config 本案名称标号.json --output 名称标号逐处表 --view accepted --fail-on-issues`

脚本仅用 Python 标准库。JSON 配置使用下列字段，段落序号从 1 开始，按所选接受态或拒绝态计算，含空段。每个段落必须归属一个明确的段落规则。先独立核对配置是否符合上段的格式来源，再不加 `--fail-on-issues` 查看候选，逐处审定后用于验收。脚本不能判断用户想要哪种格式；错误配置也可能得到零异常。

```json
{
  "require_canonical_names": true,
  "components": [
    {"number": "223", "name": "安装座", "aliases": ["环形安装座"]},
    {"number": "22", "name": "上盖", "aliases": []},
    {"number": "342", "name": "插拔上盖", "aliases": []}
  ],
  "regions": [
    {"name": "摘要", "start_paragraph": 1, "end_paragraph": 4, "mode": "exempt", "style": "either"},
    {"name": "权利要求", "start_paragraph": 5, "end_paragraph": 22, "mode": "required", "style": "parenthesized"},
    {"name": "说明书前部", "start_paragraph": 23, "end_paragraph": 79, "mode": "exempt", "style": "either"},
    {"name": "具体实施方式", "start_paragraph": 80, "end_paragraph": 108, "mode": "required", "style": "bare"}
  ],
  "exceptions": [],
  "parenthetical_name_exceptions": []
}
```

`optional` 表示该段允许省号，但出现的标号仍查一致性；`exempt` 表示该段的名称不要求尾随标号，整段例外必须有模板或用户依据。标记表前置编号需人工按每个表项核对，不能套用尾随数字检查。例中段号只演示配置形式，实际案件重新提取段落。

最终分册及合订稿开启 `require_canonical_names: true`，每个标号只配置一个 `name`。配置中的 `aliases` 仍参与匹配，但最终稿使用别名会报告 `noncanonical_name`，即使号码正确或该段为 `exempt` 也不跳过命名检查。未配置该开关或设为 `false` 时保留旧版的别名识别行为，适合输入资料或拒绝态底稿追溯；不能把历史模式的零异常当作最终命名通过。

正式名旁紧邻的“名称（别名）”及前置编号表项中的文字括号，另列入 JSON 的 `parenthetical_name_candidates`。同号已登记别名标为 `parenthetical_alias`；未识别的表项括号文字仅为人工候选，不据此推断词义。普通的权项数字括号、正文解释和公式不被批量删除；例如“安装座（223）”“安装座223（用于支撑）”和正常公式括号不构成括号别名。表项括号中明显的功能说明可略过候选，但未知形态或名称仍须人工核读。前置编号是否正确仍按表项人工验收。

输出 JSON 保存每个名称的段落、字符起点、别名、预期与实有标号、上下文及状态；CSV 保存同一逐处表。跨 Word 字号、加粗等 run 的名称仍合并识别。接受态读取新增文字、排除删文，拒绝态反向读取。段落标记修订若留有文字，会列出边界待复核，先用 Word 验证物化结果再用于段落验收。

`label_status` 和 `naming_status` 分开保留诊断。例如别名及数字格式同时有问题时，`status` 为 `noncanonical_name`，`label_status` 仍记录 `label_style`。`--fail-on-issues` 也会因未核定的括号命名候选退出1；不是只看 `summary.issues` 就可放行。没有候选不证明未知别名不存在，字典外称谓、并列省略及结构类型仍须通读。

每条例外使用精确位置，须写明当前词指向何物及依据。

```json
{"paragraph": 88, "name": "安装孔", "start": 146, "reason": "此处属于灯板的安装孔，图9及本句安装关系可核；并非标记表中遮光罩安装孔2326。"}
```

`start` 为所选态段落内从 0 开始的字符位置。每条只豁免该处，修改文字后若坐标失效脚本会中止，要求重新审定。不得为清空异常而对同名词设跨篇豁免。错误未知标号、已知但不匹配的标号和标号格式分别报告；未列入名称字典的部件及图上落点仍须人工核对。

最终模式中的别名不能被原有数字格式例外顺带豁免。确认为形态类型、第三方原文引用或非本案对象的精确出现，才可在该条 `exceptions` 增加 `non_component_usage: true` 并写明语义依据，例如“采用托杯结构”中的类型词。此时保留原 `naming_status` 供追溯，`status` 记 `accepted_exception`。理由仅为“同号”“原来如此”不成立；本案正式部件第二名称仍须统一。

括号候选如确为正常解释，使用独立的精确配置，不能用标号格式例外代替：

```json
{"paragraph": 45, "start": 4, "text": "安装座（圆形结构）", "reason": "此表项括号仅说明已核形态，正式名仍为安装座，未另命名。"}
```

该条放入 `parenthetical_name_exceptions`；段号、起点及完整候选文字须同时匹配，改字后失效即重核。若括号内另有已登记别名，其名称出现仍须单独处理，不能通过核定外层括号来放过正式同物异名。

## 配置与错误样本复验

在隔离工作副本使用少量已知样本检验当前配置：权项“固定座（10）”应符合括号政策；说明书“固定座10”应符合裸标号政策，而故意改成“固定座（10）”应报告`label_style`；同段正常说明性括号不应因此被删除或误判。检查未能发现已知错误时，先纠正配置或方法，不据零异常放行。保留配置及来源与当前文件的绑定；上位程度、必要性和图上落点不由这项数字格式检查证明。

运行 `python scripts/test_component_canonical_names.py` 验证最终命名回归：正式名同号通过、历史别名在历史模式可读而最终模式报错、标记表括号别名不能因 `exempt` 漏过、未知括号候选须核定、数字及解释公式括号保持、精确结构类型例外可追溯，以及接受态／拒绝态各按所审版本核名。样例均为合成文字，不替代本案逐处审核。

## 交付验收

保存所审稿和改后稿的完整逐处记录。接受态正文与拟定稿一致，拒绝态能还原底稿。最终净稿及修订稿均重跑同一标准，全部候选有处理结论；每条例外和确实缺少图证的部位写明依据。改动处看实际渲染页，连查相同部件在其他位置和图中的名称及标号。报告写清检查了哪些段和图、出现次数和例外次数，局部核查不写成全稿完成。
