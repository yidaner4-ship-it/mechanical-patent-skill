# 机械专利撰写

从用户指定的材料和稿件版本出发。明确本轮是初稿、局部修改、整套五书还是单独核图。续改沿用用户认可的底稿。材料有冲突时，注明影响到的结构关系或权项，先完成已有依据的部分。将计算、试验或现场尚未核实的结果和已知事实区分开。

## 起草与改稿

独权必须上位、简洁、抽象，正式稿同一特征使用一个名称。机械新特征先交代归属或设置关系，再展开细节及作用；同句可完成引入，按实际引用链核查，不为介绍层次把实施例细节上提独权。先读同包[独权保护层次与特征名称](../shensheng-patent-qa/references/claim-scope-and-names.md)，按共同细则取舍和同步，不把实施例清单、全部模块或全部检索区别堆入独权。具体实例仍充分披露，材料和申请阶段边界继续适用。

1. 先梳理核心结构、配合关系和实际工况，确定改进解决的具体问题。用一张内部对照表将权项限定关联到交底、模型或说明书。可动部件写清相对谁运动，接合和限位写明作用的部件及状态。
2. 权利要求1优先用有说明书支持的上位名称，简短写出核心部件和必要配合。起草后逐项试删具体导向、驱动、固定、形状和尺寸，判断删去或概括后核心配合是否仍成立、保护范围是否有支持。有保护价值的具体方案作为从属项，其余实施细节交给说明书。简单方案直接写，复杂配合按需要分段。权项数量按本案要求。
3. 从属项按实际依赖引用，集中写新增限定。说明书交代结构、连接、状态及效果的因果关系，具体实施方式从整机到局部配合，保留各层权项所需教导。摘要概括核心构造与直接效果。全文使用稳定术语、图号及标号。
4. 修订后复查权项先行基础、累计限定、说明书支持及范围变化，同步核对摘要、附图说明、标记和对应图页。专利性判断以实际检索和核读的证据为依据，并标明未核范围。

## 套版和附图

默认每个独立视图单独占页，按说明书首次实质引用顺序连续编号，图体在版心水平及垂直居中，图号在页脚居中，局部视图在真实裁断处补断裂线。采用已有模板时，将这些要求落实到附图页，其余文字格式沿用母版。用户当次明确指定其他版式时按当次要求处理。

需要制作五书或审附图时，读取[成品检查方法](references/delivery-review.md)。有用户指定或已确认的模板，就从其副本制作正式文件，按实际成品复核版式。沿每根引线全长检查落点、交叉、贴线、整箭和文字间隙。改线后复核邻线及受影响图页，使用同一确认图稿更新交付副本。

## 成稿后默认质检

本插件同时包含[申晟专利独立质检](../shensheng-patent-qa/SKILL.md)，安装撰写插件即取得该入口、逐处扫描脚本、核查方法及报告格式。实际初稿或改稿文件产生后、最终交付前，默认读取并执行同包质检，无须用户再次提出。用户当次明确限定审阅范围、要求跳过或只要尚未成稿的讨论时，遵从其要求；局部改稿检查修改位置及必要的关联一致性，未受影响且文件、依据、用户要求、规则、范围和阶段均未变的材料复用已有结果；已被指出的漏检结论须重核。

将有效文件、技术依据和检查范围交给未参与本轮起草的独立审阅者。逐条核实意见，有依据且已授权的错误整改后同步实际交付副本，再复查权项、正文、每次名称标号及对应图面，记录已解决和未核事项。无独立审阅条件时完成能做的检查，并明确写“独立质检未完成”；不得把起草者自检或扫描器通过写成独立审稿通过。

按同包报告格式保存审核、整改复核及最终文件摘要值。核心质检使用随包方法，默认输出 Markdown 记录；本机已有兼容上游组件时可追加 HTML 报告，无需为核心质检另装技能或向外上传稿件。交付正文与待确认事项分别保存，清理交付副本的身份信息、历史修订及其他不属于交付内容的元数据，再检查实际文件可打开、内容及图页完整。
